# Feature Specification: 小红书风格内容社区前端

**Feature Branch**: `N/A`（前端子系统独立管理）

**Created**: 2026-08-07

**Status**: Draft

**Input**: User description: "我要有一个好看的，设计语言统一的，安全的前端。创建一个类似小红书的网页客户端。"

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 浏览发现信息流（首页瀑布流） (Priority: P1)

用户打开首页后，看到一个具有视觉吸引力的瀑布流卡片网格（类似小红书），可以快速浏览各类图文帖子。卡片以图片为主体，下方展示标题、作者和互动信息。用户可以无限滚动加载更多内容，并可在「推荐」「关注」「同城」三个信息流之间切换。

**Why this priority**: 信息流浏览是内容社区最核心的用户体验。首页是用户进入后的第一视觉接触点，必须给人「好看」的第一印象，直接决定用户留存。

**Independent Test**: 用户登录后进入首页，可以看到瀑布流卡片并滚动加载更多；切换 Tab 后显示对应内容流。可独立测试：启动前端（Mock 模式），验证瀑布流布局和分页是否正确。

**Acceptance Scenarios**:

1. **Given** 用户已登录并进入首页，**When** 页面加载完成，**Then** 显示双列或多列瀑布流卡片网格，卡片以图片为主体（图片占卡片 60% 以上视觉面积），每个卡片显示封面图、标题、作者昵称、点赞数
2. **Given** 用户在首页信息流，**When** 滚动到页面底部，**Then** 自动加载下一页内容，显示加载指示器
3. **Given** 用户在首页「推荐」Tab，**When** 点击「关注」Tab，**Then** 切换为关注用户的信息流内容；再次点击「同城」Tab 同理
4. **Given** 用户首次进入首页，**When** 后端返回空列表，**Then** 显示「暂无内容」空状态提示，而非空白页
5. **Given** 用户在首页，**When** 网络请求失败，**Then** 显示错误提示（由请求拦截器统一 toast），列表保留已加载的内容不丢失
6. **Given** 用户使用移动端（≤ 560px 宽），**When** 浏览首页，**Then** 瀑布流自动适配为 2 列，卡片尺寸适配移动端

---

### User Story 2 - 查看帖子详情与互动 (Priority: P1)

用户点击瀑布流中的卡片，进入帖子详情页。详情页展示完整的帖子内容（标题、正文、多图/视频），以及作者信息、互动数据（点赞/收藏/评论数）。用户可以点赞、收藏该帖子，也可以关注/取关作者。

**Why this priority**: 帖子详情是用户从浏览到参与的核心转化节点。详情页承载了所有互动操作，是社区活跃度的关键。

**Independent Test**: 从首页点击任意卡片 → 进入详情页 → 看到完整内容 → 执行点赞/收藏操作 → 互动状态即时更新。可独立测试：Mock 一条 FeedDetail 数据，验证所有互动按钮的状态切换。

**Acceptance Scenarios**:

1. **Given** 用户点击一个瀑布流卡片，**When** 进入帖子详情页，**Then** 展示完整的帖子标题、描述、媒体文件（图片网格/视频）、作者信息（头像+昵称+关注状态）、发布时间、地理位置
2. **Given** 用户在详情页，**When** 点击点赞按钮，**Then** 点赞状态立即切换（空心→实心），点赞数 +/- 1
3. **Given** 用户在详情页，**When** 点击收藏按钮，**Then** 收藏状态立即切换，收藏数 +/- 1
4. **Given** 用户查看他人帖子，**When** 点击「关注」按钮，**Then** 关注状态切换为「已关注」；再次点击取消关注
5. **Given** 用户查看自己的帖子，**When** 页面加载，**Then** 显示「删除」按钮（非关注按钮），点击删除后弹出确认 → 确认后跳转首页
6. **Given** 帖子没有封面图，**When** 进入详情页，**Then** 显示占位底色而非破损图

---

### User Story 3 - 评论互动（楼中楼） (Priority: P2)

用户在帖子详情页可以查看和发表评论。评论支持一级评论列表、子回复（楼中楼）、展开更多回复。用户可以点赞评论、回复他人的评论，也可以删除自己的评论。

**Why this priority**: 评论是用户参与讨论的核心功能，但相比浏览和互动（P1），它属于次优先的社交功能。

**Independent Test**: 在帖子详情页底部输入评论 → 发送 → 评论出现在列表顶部；点击某条评论的「回复」→ 输入→ 发送 → 子回复出现。可独立测试：Mock 评论数据，验证评论发表/回复/点赞/删除全流程。

**Acceptance Scenarios**:

1. **Given** 用户在帖子详情页，**When** 向下滚动到评论区，**Then** 显示评论列表（含热评优先），每个评论显示作者头像、昵称、内容、时间
2. **Given** 用户在评论区，**When** 在输入框输入内容并回车或点击发送，**Then** 评论发表成功，出现在列表顶部
3. **Given** 用户看到某条评论，**When** 点击「回复」，**Then** 输入框显示「回复 @用户名」，发送后生成子回复
4. **Given** 一级评论有子回复且未全部展开，**When** 点击「展开全部 N 条回复」，**Then** 加载并展示所有子回复
5. **Given** 用户点击评论的点赞按钮，**When** 该评论未被自己点赞，**Then** 点赞状态切换，点赞数 +1
6. **Given** 用户看到自己的评论，**When** 点击「删除」并确认，**Then** 评论从列表中移除

---

### User Story 4 - 个人主页与社交关系 (Priority: P2)

用户可以查看自己和他人的个人主页。个人主页展示用户信息（头像、昵称、简介、统计数据：关注/粉丝/帖子数）、该用户的帖子网格，以及关注/粉丝列表。

**Why this priority**: 个人主页是社交关系链的承载页，支持用户发现和关注他人，但核心浏览体验（P1）优先。

**Independent Test**: 点击任意作者头像 → 进入其个人主页 → 看到用户信息和帖子列表；点击关注/粉丝统计 → 进入关系列表。可独立测试：Mock 用户数据，验证个人主页和关系列表的数据展示。

**Acceptance Scenarios**:

1. **Given** 用户点击某个作者头像/昵称，**When** 进入该用户个人主页，**Then** 显示头像、昵称、简介、关注数/粉丝数/帖子数统计，以及该用户的帖子网格
2. **Given** 用户查看自己的主页，**When** 页面加载，**Then** 显示「编辑资料」按钮（非关注按钮）
3. **Given** 用户查看他人主页，**When** 点击「关注」，**Then** 按钮变为「已关注」，粉丝数 +1
4. **Given** 用户点击关注数，**When** 进入关注列表，**Then** 显示关注的用户列表（含关注/取关操作）

---

### User Story 5 - 发布帖子 (Priority: P2)

用户可以发布新帖子，包括输入标题、正文描述、上传图片/视频文件。

**Why this priority**: 内容发布是社区内容供给的来源，但对于消费者用户，浏览（P1）比发布更重要。

**Independent Test**: 点击首页 FAB → 进入发布页 → 上传图片 → 填写描述 → 点击发布 → 成功跳转新帖子详情。可独立测试：Mock 上传流程，验证发布表单校验和提交逻辑。

**Acceptance Scenarios**:

1. **Given** 用户点击右下角发布按钮，**When** 进入发布页，**Then** 显示标题输入框、描述输入框、媒体上传入口
2. **Given** 用户在发布页，**When** 未上传任何媒体点击发布，**Then** 提示「请先上传图片或视频」
3. **Given** 用户上传图片后，**When** 点击发布（含描述），**Then** 按钮变为「发布中…」并禁用，成功后跳转到新帖子详情
4. **Given** 用户上传视频，**When** 发布页加载，**Then** 要求必填视频封面

---

### User Story 6 - 登录与注册 (Priority: P3)

新用户注册账号，已有用户登录系统。登录后自动跳转到首页。

**Why this priority**: 认证是系统入口，但功能核心是登录后的内容浏览体验。且现有登录注册已有基础实现，本次仅需视觉优化。

**Independent Test**: 访问 `/login` → 输入用户名密码 → 登录成功跳转首页；访问 `/register` → 填写信息 → 注册成功跳转首页。

**Acceptance Scenarios**:

1. **Given** 未登录用户访问任何页面，**When** 路由守卫触发，**Then** 自动跳转到登录页面
2. **Given** 用户在登录页，**When** 输入错误凭据点击登录，**Then** 显示错误提示
3. **Given** 新用户在注册页，**When** 填写用户名/昵称/密码点击注册，**Then** 注册成功自动登录并跳转首页

---

### Edge Cases

- 图片加载失败时显示占位底色，不暴露破损图标
- 瀑布流中图片高度不一致（不同长宽比），卡片高度自适应
- 用户头像为空时显示首字母兜底占位
- 长昵称/长标题在卡片中正确截断（CSS text-overflow）
- 网络离线时列表不崩溃，保留已加载数据
- 并发操作（快速双击点赞/收藏）不会产生重复请求
- 评论输入框为空时不允许发送
- 移动端键盘弹出时评论输入框不被遮挡
- 用户被删除/注销后，其帖子和评论的展示行为

---

## Requirements *(mandatory)*

### Functional Requirements

#### 视觉设计

- **FR-001**: 首页 MUST 使用瀑布流布局，卡片高度自适应图片比例，列数根据视口宽度自动适配（大屏多列、小屏两列）
- **FR-002**: 瀑布流卡片 MUST 以图片为主体，图片占卡片视觉面积的 60% 以上，图片底部带有半透明渐变遮罩，遮罩上显示点赞数
- **FR-003**: 所有视觉属性（颜色、字号、间距、圆角）MUST 统一由 Design Token 系统管理，禁止在页面代码中硬编码视觉值
- **FR-004**: 页面 MUST 采用统一的视觉语言：浅灰底色、白色卡片、品牌红强调色、统一的圆角和间距
- **FR-005**: 卡片 MUST 在鼠标悬停时有微动效反馈（轻微上浮和阴影变化），图片在悬停时有轻微缩放效果
- **FR-006**: 侧边导航 MUST 包含图标和文字，按功能区域分组（发现、个人收藏、用户设置），底部展示当前登录用户信息和退出选项

#### 信息流

- **FR-007**: 首页 MUST 支持「推荐」「关注」「同城」三类信息流，Tab 样式为胶囊标签，当前选中的 Tab 使用品牌色背景
- **FR-008**: 首页信息流 MUST 支持 cursor 无限滚动加载，滚动到底部自动加载更多
- **FR-009**: 帖子详情页 MUST 展示完整帖子信息：标题、正文、媒体文件、作者信息、发布时间、地理位置
- **FR-010**: 帖子媒体 MUST 支持图片网格（3列缩略图）和视频播放

#### 互动操作

- **FR-011**: 用户 MUST 可以点赞/取消点赞帖子，状态即时切换
- **FR-012**: 用户 MUST 可以收藏/取消收藏帖子，状态即时切换
- **FR-013**: 用户 MUST 可以关注/取消关注其他用户
- **FR-014**: 评论 MUST 支持一级评论发表、子回复（楼中楼）、评论点赞、评论删除
- **FR-015**: 用户 MUST 只能删除自己的帖子和评论（权限校验）

#### 个人主页

- **FR-016**: 个人主页 MUST 展示用户头像、昵称、简介、关注/粉丝/帖子统计
- **FR-017**: 个人主页 MUST 以网格形式展示该用户的帖子列表

#### 安全

- **FR-018**: 所有后端返回的大整数 ID（Snowflake int64，超过 JS 安全整数范围）MUST 在数据解析时转换为字符串表示，防止精度丢失导致数据错乱
- **FR-019**: 所有用户生成内容 MUST 通过安全的文本渲染方式展示，MUST NOT 执行动态代码或将 HTML 字符串直接注入 DOM
- **FR-020**: 密钥和凭证 MUST NOT 存放在前端静态配置中，上传凭证 MUST 由后端临时签发下发
- **FR-021**: 认证失效（会话过期/Token 无效）MUST 由统一机制处理：清除本地登录态 → 跳转到登录页面

#### 状态覆盖

- **FR-022**: 所有列表/数据页面 MUST 实现三种状态：加载中（Loading）、空数据（Empty/暂无内容）、错误（Error/网络异常）
- **FR-023**: 所有异步按钮 MUST 在提交中时禁用（`disabled`）并显示加载文案（如「发布中…」），防止重复提交
- **FR-024**: 所有危险操作（删除帖子/评论）MUST 进行二次确认

#### 响应式

- **FR-025**: 所有页面 MUST 同时适配桌面端和移动端（≤ 560px），移动端瀑布流自动变为 2 列
- **FR-026**: 侧边导航在 ≤ 768px 时 MUST 折叠为顶部横向导航

#### 可访问性

- **FR-027**: 交互元素 MUST 使用语义化 HTML（`<button>` / `<a>`）
- **FR-028**: 所有可交互元素 MUST 支持键盘 Tab 聚焦，`focus-visible` 可见
- **FR-029**: 图片 MUST 设置 `alt` 属性（内容图描述，装饰图空字符串）
- **FR-030**: 动效 MUST 包裹 `@media (prefers-reduced-motion: reduce)` 禁用

### Key Entities

- **FeedCard（瀑布流卡片）**: 帖子的列表展示形态，包含封面图片、标题、作者昵称、点赞数、互动状态。用于瀑布流和网格列表
- **FeedDetail（帖子详情）**: 帖子的完整信息，包含标题、正文、媒体文件列表、作者详情（含关注状态）、互动统计（点赞/收藏/评论数）、当前用户互动状态
- **CommentEntry（评论条目）**: 一级评论，包含评论内容、作者、时间、点赞数、点赞状态、子回复预览
- **CommentReply（子回复）**: 评论的回复，包含内容、作者、被回复人引用
- **UserDetail（用户详情）**: 用户主页信息，包含头像、昵称、简介、城市、关注/粉丝/帖子统计、是否已关注
- **AuthSession（认证会话）**: 当前登录用户的信息和 JWT Token

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 用户进入首页后，瀑布流首屏内容在 2 秒内渲染完成
- **SC-002**: 瀑布流滚动加载下一页内容时，新卡片在 500 毫秒内出现
- **SC-003**: 点赞/收藏/关注操作的状态切换在 100 毫秒内完成视觉反馈（乐观更新）
- **SC-004**: 所有页面在移动端（≤ 560px）和桌面端（> 560px）均无布局错乱、溢出或内容截断
- **SC-005**: 页面首次加载的灯塔评分（FCP / LCP）在标准网络下达到良好级别
- **SC-006**: 100% 的视觉属性（颜色/字号/间距/圆角）引用 Design Token，无硬编码值
- **SC-007**: 整个前端 zero `dangerouslySetInnerHTML` 和 zero `eval` 调用（可通过 CI 脚本静态扫描）
- **SC-008**: 所有异步操作按钮在请求进行中处于禁用状态，100% 防止重复提交
- **SC-009**: 键盘 Tab 键可遍历页面所有可交互元素，无障碍访问满足基本要求
- **SC-010**: 用户可以在没有后端的情况下（Mock 模式，`VITE_USE_MOCK=true`）完整体验所有页面和流程

## Assumptions

- 后端 API 接口和 gRPC 服务已经完成并稳定，接口契约（`.api` / `.proto`）无变更
- Mock 模式（`VITE_USE_MOCK=true`）已由现有 axios adapter 支持，本次改造不破坏 Mock 体验
- 前端技术栈约束不变：React 18 + TypeScript + Vite 5 + 单一全局 CSS（不引入任何新 UI 库或样式方案）
- 现有公共组件（`Layout`、`Avatar`、`FeedCardGrid`、`useCursorList`、`toast`）的接口保持向后兼容
- 移动端以现代浏览器（iOS Safari 14+、Android Chrome 90+）为目标，不兼容 IE
- 图片资源均来自 COS + CDN，前端不参与图片裁剪/压缩
- 搜索功能本次不做实现（后端搜索接口未完成），搜索栏保留占位状态
- 推送通知/IM 消息为后续版本功能，本次不涉及
- 暗色主题不在本次范围
