# 创作者作品表现分析

> 定义作品指标口径与公式、同类内容匿名对比方法、漏斗诊断规则与建议生成边界。属实施阶段四。

---

## 1. 概述与定位

创作者提问「分析我这条视频为什么播放效果不好」，系统必须给出**带数字、可比较、能定位环节**的结论，而不是「内容质量较低」这类空话。

职责切分：

| 环节 | 执行者 |
|------|--------|
| 指标计算、同类对比、漏斗定位、阈值判定 | Go 代码（Interaction RPC + Agent 后端） |
| 文字组织与建议表述 | 模型（仅能引用后端给出的数字与结论码） |

红线：**分析结论中的所有数字必须来自指标接口**，模型不得计算、不得编造、不得推断未提供的指标。

## 2. 指标定义

原子指标（来自 `feed_metrics_hourly` + Redis 当前小时，见 [03](./03-behavior-event.md)）：

| 指标 | 字段 | 口径 |
|------|------|------|
| 曝光量 | `expose_count` | 真实可视曝光（同一请求同一feed 只计一次） |
| 播放量 | `play_count` | 起播次数 |
| 有效播放量 | `effective_play_count` | ≥3s 或 ≥50% 时长 |
| 完播量 | `finish_count` | ≥95% 时长 |
| 快速划走量 | `skip_count` | 起播后 <3s 离开 |
| 观看总时长 | `watch_duration_ms` | 累计播放毫秒 |
| 点赞/收藏/评论/分享量 | `like/collect/comment/share_count` | 与 Interaction、Comment 口径一致 |

派生率（分母为 0 时返回 `null` 而非 0，避免误导）：

| 指标 | 公式 |
|------|------|
| 播放率 | `play / expose` |
| 有效播放率 | `effective_play / expose` |
| 完播率 | `finish / play` |
| 快速划走率 | `skip / expose` |
| 平均播放时长 | `watch_duration_ms / play` |
| 点赞率 | `like / play` |
| 收藏率 | `collect / play` |
| 评论率 | `comment / play` |
| 分享率 | `share / play` |

分母口径必须在回答中体现：**播放率、有效播放率、快速划走率以曝光为分母**（衡量「是否愿意点开」）；**完播率与互动率以播放为分母**（衡量「点开后的体验」）。

时间窗：默认最近 24 小时；支持 `1h / 24h / 7d / all`。跨作品对比必须同窗口。

## 3. 同类对比（Peer Metrics）

分组维度（三重匹配，逐级放宽）：

| 级别 | 条件 | 最少样本 |
|------|------|:---:|
| L1 | 同 `category` + 发布时间 ±72h + 同时长分桶 | 20 |
| L2 | 同 `category` + 同时长分桶（近 30 天） | 20 |
| L3 | 同 `category`（近 30 天） | 20 |
| 兜底 | 全站视频（近 7 天） | 100 |

时长分桶：`0-15s` / `15-30s` / `30-60s` / `60s+`。

匿名与聚合规则：

- 只返回统计量：`avg`、`p25`、`p50`、`p75`、`sample_size`。
- 样本不足则降级到下一级；全部不满足返回 `insufficient_sample=true`，Agent 必须说明「同类样本不足，暂不做对比」。
- **禁止**返回任何单条 feed 的指标、feed_id 列表或作者信息。
- 接口要求登录并限流，防止被用于批量探测行业数据。

## 4. 漏斗诊断

把「播放效果差」拆成可定位的四段漏斗：

```text
曝光 ──播放率──▶ 播放 ──(1-快速划走率)──▶ 留住前3秒 ──完播率──▶ 完播
                └─ 互动率 ─▶ 点赞/收藏/评论
```

判定规则（相对同类中位数 `p50`）：

| 结论码 | 判定条件 | 定位环节 |
|--------|----------|----------|
| `LOW_CTR` | 播放率 < 0.8 × peer.p50 | 封面 / 标题 / 首帧吸引力 |
| `EARLY_DROP` | 快速划走率 > 1.2 × peer.p50 | 视频前 3 秒信息表达 |
| `MID_DROP` | 完播率 < 0.8 × peer.p50 且快速划走率正常 | 中后段节奏/内容 |
| `LOW_INTERACTION` | 播放正常但点赞率与收藏率均 < 0.8 × peer.p50 | 内容价值感 / 缺少引导 |
| `LOW_EXPOSURE` | 曝光量 < peer.p25 且发布 > 6h | 分发不足，非播放问题 |
| `HEALTHY` | 各项均 ≥ 0.9 × peer.p50 | 无明显短板 |
| `INSUFFICIENT_DATA` | 曝光 < 200 或播放 < 50 | 数据量不足，不出诊断结论 |

诊断输出为结论码 + 具体数字，模型只做文字组织。期望回答形态：

```text
该视频最近 24 小时获得 8,214 次曝光，播放率为 10.7%，低于同类视频中位数 15.2%。

前三秒快速划走率为 61.4%，高于同类中位数 43.8%。已经开始播放的用户中，完播率为 48.3%，接近同类水平（46.9%）。

主要问题集中在「是否被点开」和「前三秒留人」两个环节，而不是视频中后段。
```

## 5. 建议生成边界

建议来源于「诊断结论码 + 内容画像事实」，且必须标注为分析建议：

| 结论码 | 可给出的建议（需有画像事实支撑） |
|--------|-------------------------------|
| `LOW_CTR` | 封面缺少核心主体（`objects` 无核心物体）或标题未包含任何 `topics` → 建议在封面与标题中前置主题词 |
| `EARLY_DROP` | 开头字幕（`transcript` 前 3 秒片段）无信息量或为寒暄 → 建议前 3 秒直接给出结论或画面亮点 |
| `MID_DROP` | 时长高于同类 p75 → 建议压缩中段 |
| `LOW_INTERACTION` | 字幕无明确引导语 → 建议结尾增加行动引导 |
| `LOW_EXPOSURE` | 属分发阶段问题，建议关注发布时段与内容垂直度，**不承诺提升曝光** |

表述要求：

- 一律使用「分析建议」表述（`建议` / `可能与…有关`），禁止因果断言。
- 禁止与画像无关的通用套话。
- 建议 ≤ 3 条，每条 ≤ 60 字。

## 6. 对外契约

`GetCreatorMetrics(feed_id, window)`（仅本人或内部用户）：

```json
{
  "feed_id": 88901,
  "window": "24h",
  "published_at": 1785302400000,
  "raw": { "expose": 8214, "play": 879, "effective_play": 402, "finish": 425, "skip": 5043, "watch_duration_ms": 6712000, "like": 63, "collect": 21, "comment": 12, "share": 4 },
  "rate": { "play_rate": 0.107, "effective_play_rate": 0.049, "finish_rate": 0.483, "skip_rate": 0.614, "avg_watch_ms": 7636, "like_rate": 0.072, "collect_rate": 0.024 },
  "data_complete": true
}
```

`GetPeerAverageMetrics(feed_id, window)`：

```json
{
  "peer_level": "L1",
  "sample_size": 137,
  "category": "户外旅行",
  "duration_bucket": "30-60s",
  "rate": {
    "play_rate":   { "avg": 0.148, "p25": 0.092, "p50": 0.152, "p75": 0.201 },
    "skip_rate":   { "avg": 0.451, "p25": 0.331, "p50": 0.438, "p75": 0.552 },
    "finish_rate": { "avg": 0.472, "p25": 0.351, "p50": 0.469, "p75": 0.585 }
  },
  "insufficient_sample": false
}
```

权限：

- `GetCreatorMetrics` 校验 `feed.author_id == ctx.user_id`，否则 `Forbidden`。
- `GetCreatorFeedList` 只返回本人作品。
- 内部用户可查任意作品，但请求记入审计日志。

## 7. 测试策略

| 层次 | 用例 |
|------|------|
| 单元 | 分母为 0 → 派生率返回 `null`，不返回 0，也不 panic |
| 单元 | 漏斗判定阈值边界（0.8 / 1.2 倍）与 `INSUFFICIENT_DATA` 触发 |
| 单元 | peer 分组降级：L1 样本 19 → 落到 L2 |
| 集成 | 查询他人作品指标 → `Forbidden` |
| 集成 | peer 结果不含任何 feed_id / author_id 字段（结构断言） |
| 集成 | Redis 当前小时数据叠加正确（刚上报事件在 24h 窗口内可见） |
| 契约 | Agent 输出中的每个数字都能在 Tool 返回 JSON 中找到（数字一致性校验器） |

## 8. 演进与 TODO

- 分段留存曲线（每秒留存率），需要播放进度心跳事件。
- 同类对比引入内容向量近邻而非仅类目，提高可比性。
- 引入发布时段、话题热度等外部因素，减少误判为「内容问题」。
- 指标迁移分析型存储后支持任意窗口与维度下钻。
