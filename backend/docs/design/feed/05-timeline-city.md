# 同城流（Timeline-City）设计方法论

> 本文档描述 Feed 同城流的实现方法论。
> 同城流的核心是「按城市聚合 + 时间倒序」，比推荐流更简单，但需要注意城市编码规范和冷启动问题。
> 不包含完整代码。

---

## 1. 问题定义

同城流 = 与当前用户同一城市的帖子，按发布时间倒序排列。

特点：

- 用户城市在注册时通过 IP 定位写入，可手动修改。
- 城市范围固定，用户量大的城市（如北京、上海）数据多。
- 对实时性要求中等，不需要像关注流那样个性化。

---

## 2. 数据模型：城市候选池

### 2.1 Redis ZSet：`feed:city:{city_code}`

- 类型：ZSet。
- member：`feed_id`。
- score：发帖时间戳（秒级）。
- 容量：2 万条/城市。
- TTL：7 天。

### 2.2 为什么每城市一个 ZSet

- 查询简单：`ZREVRANGE feed:city:440300 0 19` 即可。
- 天然按城市隔离，不需要过滤。
- 不同城市的数据量差异大，独立 ZSet 便于容量管理。

---

## 3. 城市编码规范

### 3.1 使用标准行政区划编码

- 采用国家标准行政区划编码，6 位数字。
- 直辖市：`110000`（北京）、`310000`（上海）、`440300`（深圳）。
- 地级市：`440100`（广州）、`330100`（杭州）。

### 3.2 同城流的粒度

- V1：精确到地级市。
- V2（可选）：精确到区县，或允许用户切换「附近 50km」。

### 3.3 用户无城市时的处理

- 若用户 `city_code` 为空，同城流返回空。
- 引导用户在个人资料中设置城市，或 frontend 通过 IP 定位补全。

---

## 4. 同城流读取流程

```
输入：user_id, city_code, page, page_size
输出：feed_id 列表

1. 从 User Service 获取用户 city_code（若前端未传）。
2. 从 feed:city:{city_code} 按 score 倒序取前 page_size × page 条。
3. 跳过前 (page - 1) × page_size 条。
4. 返回当前页 feed_id。
```

分页方式：Offset。

原因：同城流按时间倒序，新增帖子在顶部，Offset 分页在翻页时可能会有少量重复，但可接受。

---

## 5. 同城池维护

### 5.1 写入时机

- 帖子发布成功后，Worker 消费 `feed.created` 事件。
- 若帖子 `city_code` 不为空，将该 feed_id ZADD 到 `feed:city:{city_code}`。
- 大V和普通用户都走同样的写入逻辑（同城流不需要推拉结合）。

### 5.2 容量控制

- 每城市池上限 2 万条。
- 超过时 ZREMRANGEBYRANK 删除最旧的。
- 城市用户数差异大，未来可按城市级别动态调整容量。

### 5.3 冷启动

- 新城市第一条帖子发布时，自动创建 `feed:city:{city_code}`。
- 无帖子的城市返回空列表。

---

## 6. 缓存策略

### 6.1 同城流热点缓存

- `timeline:{user_id}:city` 缓存前 2 页 JSON，TTL 1 分钟。
- 比关注流短，因为同城流持续有新内容进入。

### 6.2 帖子详情缓存

- 同城流返回 feed_id 列表后，调用 BatchGetFeeds 获取详情。
- BatchGetFeeds 内部使用 `feed:{feed_id}` 缓存。

---

## 7. 边界场景

| 场景 | 处理 |
|------|------|
| 城市编码不存在 | 返回空列表，记录 warn log |
| 同城池为空 | 返回空列表，前端展示「暂无同城动态」 |
| 用户切换城市 | 删除旧 `timeline:{user_id}:city`，读取新城市池 |
| 帖子被删除 | 从对应 `feed:city:{city_code}` ZREM |
| 用户城市为空 | 直接返回空 |

---

## 8. 与推荐流的对比

| 维度 | 推荐流 | 同城流 |
|------|--------|--------|
| 数据来源 | 全局池 | 城市池 |
| 排序 | 随机 × 时间衰减 | 纯时间倒序 |
| 容量 | 10 万条全局 | 2 万条/城市 |
| 分页 | Offset / Cursor | Offset |
| TTL | 30 天 | 7 天 |
| 个性化 | 可选 | 无 |

---

## 9. 扩展方向

| 方向 | 方法 |
|------|------|
| 附近的人 | 使用 GeoHash 或 Redis Geo 数据结构 |
| 多城市聚合 | 用户可同时关注多个城市，合并多个 city 池 |
| 同城热门 | 按互动计数额外维护 `feed:city_hot:{city_code}` |
