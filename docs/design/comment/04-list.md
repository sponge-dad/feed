# 评论列表查询方法论

> 本文档描述 Comment 服务「评论列表」读模块的规范与约束。
> 重点：一级评论分页、每楼子回复预览、查看全部回复分页、用户信息批量填充（防 N+1）。

---

## 1. 三类读接口的职责

| 接口 | 用途 | 数据来源 |
|------|------|---------|
| ListComments | 帖子详情页首屏：一级评论分页，每楼附前 N 条子回复预览 | MySQL + Redis(count) + User(批量) |
| ListReplies | 点「查看全部回复」：某根评论下全部子回复分页 | MySQL + User(批量) |
| GetCommentCount / BatchGetCommentCount | 评论总数（单帖 / 批量） | 见 `05-stats.md` |

---

## 2. 一级评论分页（ListComments）

- **过滤**：`feed_id = ? AND root_id = 0 AND status = 1`。
- **排序**：一级评论倒序（新评论在前），按 `created_at DESC`。
- **分页方案决策**：
  - 默认用 **Offset 分页**（`page + page_size`）：实现简单，一级评论单帖通常量级可控。
  - 若预期单帖一级评论可能极大，改用 **Cursor 分页**（`created_at` + `id` 组合游标，向下翻页避免漏评/重复）。
  - 决策记录：首版本用 Offset，预留 Cursor 改造空间。
- **返回结构**：一级评论列表 + 每个一级评论对象内嵌 `preview_replies`（前 N 条子回复，见下）。

---

## 3. 每楼子回复预览（preview_replies）

- 对每个一级评论 `root_id = R`，取 `feed_id=? AND root_id=R AND status=1 ORDER BY created_at ASC LIMIT N`（`N=3`）。
- **批量取，禁止逐楼查**：先用一条 SQL 按 `root_id IN (一级评论id列表)` 取出所有楼的前 N 条（或用排序+分组），再在内存按 root_id 分组。
  - 实现约束：避免"先查一级列表再 for 循环查回复"的 N+1。必须用一次聚合查询或 IN 批量查询后分组。
- 预览不足 N 条时如实返回，前端不显示「查看全部」或显示「共 M 条」。

---

## 4. 查看全部回复分页（ListReplies）

- **过滤**：`root_id = ? AND status = 1`。
- **排序**：子回复正序（`created_at ASC`），还原对话时间线。
- **分页**：子回复用 **Cursor 分页**（`created_at` + `id`），因为可能长列表滚动。
- **约束**：`root_id` 必须是合法存在的根评论（`status=1`），否则返回 `CommentNotFound=13001`。
- **与方案 A 的自洽**：方案 A（见 `03-delete.md`）下根评论被删后整楼折叠，一级列表不再展示该根、也不提供"查看全部回复"入口，因此"根必须 status=1"的校验成立，与计数口径"根已删楼不计入 `comment_count`"相互一致。已删根楼下的子回复作为历史数据保留、不再可达。

---

## 5. 用户信息批量填充（防 N+1）

列表返回前，需把 `user_id` / `reply_user_id` 对应的昵称、头像补上：

1. 收集本次响应所有 `user_id` 与 `reply_user_id`，去重得到 id 集合。
2. **一次批量 RPC** 调 User 服务（如 `BatchGetUser`），拿到 `user_id → {nickname, avatar}` 映射。
3. 在内存拼装到每条 CommentInfo。
4. User 服务不可用时：降级返回评论但不带用户信息（或默认匿名），不因此失败整个列表请求。

**约束**：
- 绝对禁止：循环内逐条调 User 服务（N+1，会压垮 User 与评论服务）。
- 建议：User 基础信息在调用方做短 TTL 本地/Redis 缓存，进一步降低下游压力。

---

## 6. 评论总数与热门置顶

- ListComments 响应附带 `total = comment_count:{feed_id}`（见 `05-stats.md`）。
- **热门置顶**：可选能力。若启用，将 `comment_hot` 中 Top-K 评论提到一级列表最前（带"热门"标记），其余按时间倒序。首版本可不置顶，仅返回总数，置顶作为后续增强。

---

## 7. 排序与展示规则（产品语义）

| 元素 | 排序 |
|------|------|
| 一级评论 | 时间倒序（最新在前） |
| 楼内子回复预览 | 时间正序（前 N 条，最旧在前） |
| 查看全部回复 | 时间正序（最旧在前，符合对话流） |
| 热门置顶（可选） | 按 like_count 降序，置顶于一级列表 |

---

## 8. 性能与边界

| 关注点 | 约束 |
|--------|------|
| 首屏 RT | 一级列表 + 预览聚合查询 + 1 次 User 批量，P99 < 50ms |
| 分页越界 | page/size 由 logic 层校验上限（如 size ≤ 100），防止恶意大页 |
| 空帖 | 返回空列表与 total=0，不报错 |
| 已删除评论 | 读过滤 status=1：子回复/一级评论自身被删则不可见；**方案 A 下根评论被删时，根本身标记"已删除"折叠、不再出现在一级列表，其下子回复作为历史数据保留但不再可达**（与 `03-delete.md` 方案 A 一致，也是计数口径"排除根已删楼"的依据）。`comment_count` 重建与列表展示共用同一可见口径 |
| 排序稳定性 | 同 created_at 用 id 兜底，避免分页重复/漏评 |
